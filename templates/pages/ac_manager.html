How the models learn

Each AC has its own machine-learning model, and the model is the main detector: it learns how that AC normally behaves and raises ML alerts when it does not. Add an AC here, send it data, then press Train now. The safety limits are an optional second alarm (switch on the Dashboard).

Data and retention

Two kinds of readings are stored. Training data (per AC, in the table the models learn from) is what each model is built from, it is never thinned and never touched by the cleanup below. Live telemetry only feeds the dashboard values and the graphs: the model scores each reading as it arrives and does not read this table, so old live readings can be removed without affecting any model or alert.

Delete Data vs Delete. Delete Data removes only the stored training readings of one AC and the model learned from them; the AC, its name, its safety limits, live telemetry and past alerts stay, and the AC shows retraining required until you collect new readings and press Train now. Delete removes the whole AC.

About the names. Use Rename to call an AC whatever you like. Without a name it is shown as AC1, AC2, ... by its position in this list, so when you delete one the others move up. Each unit keeps a fixed device code underneath, which is what your ESP32 sends, and it is shown in grey whenever it differs from the name. Deleting an AC permanently removes its readings and its model; live telemetry and past alerts are not affected. Turn off or reconfigure the device first, or its next reading will bring the AC back.

Safety limits

These numbers decide what counts as a problem for this AC and what the alerts say. Change them when this AC is bigger or smaller than the default. A ⚡ instant limit sends an alert straight away when it is passed, even before the AI has learned anything. Safety limits only drive the Safety Limit Alerts (switch on the Dashboard); the ML model does not use them. Humidity only alerts when it is too low.
